# B2B 90 天获客方案

[English](README.md) | [简体中文](README.zh-CN.md)

> 为本地 B2B 服务型企业产出「90 天可执行获客方案」，配套一份询盘追踪台账。

## 这是什么

> **脱敏说明。** 本 README 已经写成通用版本。技能文件本身可能仍带有内部域名、主机名或本机绝对路径。发布前请先跑一遍扫描（见 `opensource-preflight-audit`），把命中的内容替换掉。

这不是一份营销战略文档。战略文档读起来很好看，什么都不会改变。

这里的产出是一份被压到"哪个渠道、哪个月、多少条询盘"这个颗粒度上的方案。方案里的一行如果追不到下周有人能做的动作，它就不该待在这里。

## 为什么开源

我们给本地服务型企业做这类方案，反复出现的问题是一样的：方案做得很漂亮，没人执行，因为它描述的是结果，不是动作。

结构本身是通用的。需求拆解的思路和台账的格式跟行业无关，所以放出来是合理的。

## 能做什么

- **需求拆到渠道和月份。** 询盘目标被分解成每个渠道、每个月的量，而不是说一次就搁那儿了。
- **每个渠道挂具体动作。** 不是描述"有这个能力"，是写清要做什么。
- **配套 Excel 台账。** 用来追询盘，方案和追踪在同一套逻辑里。
- **两份交付物，一套逻辑。** Word 方案和 Excel 台账描述的是同一个结构，不会互相走偏。

## 怎么用

说清业务和目标：

- "给某某业务做一份 90 天获客方案"
- "三个月，这是我要的询盘量"
- "该用哪些渠道，各自要拿多少条"

它会先问业务参数，然后把方案和台账一起产出来。

## 注意与边界

1. **渠道组合是判断，不是公式。** 技能负责把决策结构化，不负责替你做决策。
2. **产能是约束。** 一个没人接得住的目，比一个诚实低一点的目标更糟。
3. **台账只有用起来才成立。** 第三周停止记录，第六周方案就读不懂了。
4. **里面对具体业务的引用是示例**，应当替换掉。
